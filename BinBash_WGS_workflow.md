# BinBash Platform WGS Workflow

This document summarizes the WGS processing workflow used on the BinBash platform. Commands are shell templates and require project-specific variables to be defined before execution.

## 1. Read quality control

```bash
fastp -i "$read1_path" -I "$read2_path" \
  -o "${sam}_1.fq.gz" -O "${sam}_2.fq.gz" \
  -j "${sam}.json" -h "${sam}.html" -w "$(nproc)"
```

## 2. Read mapping

Choose the mapping command according to the reference genome.

### Standard mapping

```bash
bwa mem -K 10000000 -M -Y -t "$thread" \
  -R "@RG\tLB:$sam\tID:$sam\tSM:$sam\tPL:$pl" \
  "$ref_path" "${sam}_1.fq.gz" "${sam}_2.fq.gz" |
  samtools sort -@ 8 --write-index -O CRAM \
    --reference "$ref_path" -o "${sam}.sort.bam" -
```

### BWA alt-aware mapping

Use this route when the reference genome has an ALT contig description.

```bash
bwa mem -K 10000000 -M -Y -t "$thread" \
  -R "@RG\tLB:$sam\tID:$sam\tSM:$sam\tPL:$pl" \
  "$ref_path" "${sam}_1.fq.gz" "${sam}_2.fq.gz" |
  /opt/bwa.kit/k8 /opt/bwa.kit/bwa-postalt.js \
    "$ref_path/$ref_basename.alt" |
  samtools sort -@ 8 -O CRAM --reference "$ref_path" \
    -o "${sam}.sort.bam" -
```

## 3. Duplicate marking and CRAM conversion

```bash
sambamba markdup -t "$thread2" --sort-buffer-size="$mem" \
  --tmpdir=/data "${sam}.sort.bam" "${sam}.sort.mkdup.bam"

samtools view -@ "$thread" -h -O CRAM --write-index --no-PG \
  -o "${sam}.sort.mkdup.cram" \
  --reference "$ref_path" "${sam}.sort.mkdup.bam"
```

## 4. Base quality score recalibration (optional)

BQSR is normally used for human WGS. For non-human species, the corresponding dbSNP or known-sites resources must be provided by the user.

```bash
gatk --java-options "-XX:GCTimeLimit=50 -XX:GCHeapFreeLimit=10 -Xms${mem}m -Xmx${mem}m -Djava.io.tmpdir=/data" \
  BaseRecalibrator -I "${sam}.sort.mkdup.cram" -R "$ref_path" \
  -O "${sam}.sort.mkdup.cram.grp" \
  --known-sites "$reca_k1" --known-sites "$reca_k2" --known-sites "$reca_k3"

gatk --java-options "-XX:GCTimeLimit=50 -XX:GCHeapFreeLimit=10 -Xms${mem}m -Xmx${mem}m -Djava.io.tmpdir=/data" \
  ApplyBQSR -R "$ref_path" -I "${sam}.sort.mkdup.cram" \
  --bqsr-recal-file "${sam}.sort.mkdup.cram.grp" \
  -O "${sam}.sort.mkdup.recal.cram"
```

## 5. GVCF calling

Run intervals in parallel with `-L "$region"`.

```bash
gatk --java-options "-Xms${mem}m -Xmx${mem}m -Djava.io.tmpdir=/data/" \
  HaplotypeCaller -R "$ref_path" -L "$region" \
  -I "${sam}.sort.mkdup.recal.cram" \
  -O "${sam}.${region}.g.vcf.gz" --emit-ref-confidence GVCF
```

Gather interval-level files using an input list containing one file path per line.

```bash
gatk --java-options "-Xms${mem}m -Xmx${mem}m -Djava.io.tmpdir=/tmp/" \
  GatherVcfs -O "${sam}.g.vcf.gz" \
  -I "${sam}.${region}.g.vcf.gz" -I ...
```

## 6. Joint genotyping

```bash
gatk CombineGVCFs -R "$ref_path" \
  --variant "${sam1}.g.vcf.gz" --variant "${sam2}.g.vcf.gz" \
  --variant "${sam3}.g.vcf.gz" -O combined.g.vcf.gz \
  -L "$region" -ip 50

gatk GenotypeGVCFs --allow-old-rms-mapping-quality-annotation-data \
  -R "$ref_path" -V combined.g.vcf.gz -O final.joint.vcf.gz \
  -L "$region" [-all-sites]
```

The `--allow-old-rms-mapping-quality-annotation-data` option is used for compatibility with GVCFs generated by GATK 3.

## 7. Chromosome-level VCF concatenation

```bash
bcftools concat -f input.list -O z -o chr1.vcf.gz
```

## 8. SNP hard filtering

```bash
gatk --java-options "-Xms1000m -Xmx1000m -Dsamjdk.compression_level=6" \
  SelectVariants -R "$ref_path" -V final.vcf.gz \
  -O final.snp.vcf.gz --select-type-to-include SNP -OVI false

gatk VariantFiltration -V final.snp.vcf.gz \
  -O final.snp.filtered.marked.vcf --filter-name "SNP_HARD_FILTER" \
  --filter-expression "QUAL < 30.0 || (vc.hasAttribute('QD') && QD < 2.0) || (vc.hasAttribute('MQ') && MQ < 40.0) || (vc.hasAttribute('FS') && FS > 60.0) || (vc.hasAttribute('SOR') && SOR > 3.0) || (vc.hasAttribute('MQRankSum') && MQRankSum < -12.5) || (vc.hasAttribute('ReadPosRankSum') && ReadPosRankSum < -8.0)"

gatk SelectVariants -V final.snp.filtered.marked.vcf \
  -O final.QC.snp.vcf.gz --exclude-filtered -OVI false
```

## 9. INDEL hard filtering

```bash
gatk --java-options "-Xms1000m -Xmx1000m -Dsamjdk.compression_level=6" \
  SelectVariants -R "$ref_path" -V final.vcf.gz \
  -O final.indel.vcf --select-type-to-include INDEL -OVI false

gatk VariantFiltration -V final.indel.vcf \
  -O final.indel.filtered.marked.vcf --filter-name "INDEL_HARD_FILTER" \
  --filter-expression "QUAL < 30.0 || (vc.hasAttribute('QD') && QD < 2.0) || (vc.hasAttribute('FS') && FS > 200.0) || (vc.hasAttribute('ReadPosRankSum') && ReadPosRankSum < -20.0)"

gatk SelectVariants -V final.indel.filtered.marked.vcf \
  -O final.QC.indel.filtered.vcf.gz --exclude-filtered -OVI false
```

## Variables and implementation notes

The workflow expects variables such as `read1_path`, `read2_path`, `sam`, `ref_path`, `ref_basename`, `thread`, `thread2`, `mem`, `pl`, `region`, and the known-sites paths to be defined by the project-specific submission script.

Before production use, confirm that the intermediate filename and format are consistent between `samtools sort`, duplicate marking, BQSR, and HaplotypeCaller. The commands above preserve the supplied workflow while making that validation point explicit.
